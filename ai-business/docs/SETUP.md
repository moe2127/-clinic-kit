# 本番接続・公開の手順

この文書は最初の接続を担当する方向けです。iPhoneからの日常操作はREADMEとOWNER-GUIDEを参照してください。
APIキーやパスワードをチャット・GitHub・HTMLへ貼らないでください。各サービスの環境変数入力欄を使用します。

## 1. Supabase（認証・保存先）

1. 所有するSupabaseプロジェクトを用意します。新規の有料契約はこの実装では作成していません。
2. SQL Editorで`supabase/schema.sql`を実行します。
3. Auth → Usersでオーナーを作成し、UUIDを`public.owners`へ追加します。オーナー登録はSQL管理者のみが行います。
4. 公開サインアップを無効にします。強い固有パスワードを設定してください。現在MFA対応の画面はありません。
5. Next.jsサーバー側へSUPABASE_URLとSUPABASE_SERVICE_ROLE_KEYを登録。service_roleはブラウザーに渡しません。
6. `kits`バケットが非公開であること、anon/authenticated向けの公開Storageポリシーがないことを確認します。

DBはMVP向けの単一JSON状態＋revision比較更新です。全更新は競合時に再試行し、費用予約・実行開始・承認が同時更新で消えないようにします。所有者1組、少量の商品向けです。複数事業者・大量商品・長期履歴にはテーブル分割とバックアップ・監視強化が必要です。ローカルデータの本番移行は自動では行いません。

## 2. OpenAI（制作・分析）

OPENAI_API_KEY、OPENAI_MODELを登録します。Chat Completionsの構造化出力（JSON Schema）とmax_completion_tokensを利用できるモデルが必要です。
最新の公式価格から、入力・出力それぞれの1MトークンあたりUSDをAI_INPUT_USD_PER_MILLION / AI_OUTPUT_USD_PER_MILLIONへ設定。USD_JPYへ予算用レートを入れます。
すべて揃うまでAPIを呼びません。単価が変更されたら運営者が設定を更新してください。

呼出し前に、最大入力32,000・最大出力12,000トークン相当＋20%の円予算を確保します。実入力は24,000バイト以下に制限。使用量が取れれば計算値に置換し、不明・中断時は予約額を保持します。SDKの自動再試行は無効です。月額上限は管理画面で設定し、上限超過の呼出しを止めます。
OpenAI側にも利用上限・通知を設定してください。為替・単価差を含む実請求額そのものの上限保証ではありません。検索等の別サービスの費用は対象外です。

## 3. 外部検索

BRAVE_SEARCH_API_KEYを登録します。Brave Search API公式エンドポイントを利用します。検索結果のURL・調査日・抜粋を保存し、原文未確認と表示。AI企画は仮説として履歴へ保存します。未接続・結果なしなら企画を止めます。
検索結果の本文を実行したり、そのURLをサーバーで無制限に取得したりしません。ユーザー入力の店舗情報・患者情報は制作AIに渡しません。

## 4. Pythonワーカー（本番のExcel生成）

VercelのNode.js関数ではPython実行を前提にできないため、`python/`を別のPythonホスティングへ配備します。ローカルだけはchild_processでPythonを呼びます。

例：Pythonホストに`pip install -r requirements.txt`、起動コマンド`uvicorn worker:app --host 0.0.0.0 --port $PORT`を設定します。Docker利用時は同梱Dockerfile（8080）を使用。コンテナのビルド・配備は今回実施していません。
両サーバーへ同じ32文字以上のランダムなPYTHON_WORKER_TOKENを登録し、Next.jsへHTTPSのPYTHON_WORKER_URLを登録。/buildはBearer認証なしでは拒否されます。ネットワーク上のアクセス制限・レート制限もホスティング側で設定してください。
AIに数式を書かせず、openpyxlの固定テンプレートを生成。30/31日・2月を実月の日数から作成します。数式を再読込して構造検査しますが、Excelエンジンによる再計算検査は未実施です。

## 5. 通知

Gmail宛にも配送できるResendを通知アダプターとして実装。RESEND_API_KEY、OWNER_NOTIFICATION_EMAIL、認証済み送信元NOTIFICATION_FROMを登録します。Gmail APIやGmailパスワードは使いません。メールは承認依頼とエラー通知のみです。
未接続・送信失敗は管理画面に記録。再送ボタンで同一IDの送信を試せます。ResendのIdempotency-Keyを利用します。

## 6. Next.js公開とCron

GitHubへこのフォルダー内を新しいリポジトリとしてアップロード（node_modules/.next/.data/.envは除外）し、Vercel等に接続。既存の静的ページと混在させないでください。商用Vercelはプラン条件に注意。
Vercelならnpm ci → npm run build、Next.js自動検出。環境変数APP_MODE=production、APP_URL=実際のHTTPS URLを設定します。
CRON_SECRETを32文字以上で設定。vercel.jsonは毎日00:00 UTC（09:00 JST）に/api/cronを実行します。Vercelでは同名のCRON_SECRETがBearerヘッダーとして使われます。他ホストでは同等の認証付きスケジューラーを設定。
15日調査、16日企画、17〜20日制作、21日QA、22日通知、翌月1日配信準備。自動運転は初期停止。管理画面で接続内容を確認し、実際の疎通テスト後に有効にします。

## 7. note公開

note公式APIには利用契約条件があります。本システムにAPIによる公開・会員管理・決済・返金は実装していません。
オーナー承認後、予定日以降にZIPを保存し、light/standard/premiumの各フォルダーから対応する素材だけをnoteの会員限定記事へ添付します。owner-onlyは会員に配布しないでください。
記事を公開し、会員側の見え方と各プランの対象を確認。管理画面のチェックリストを確認し、公開記事URLを記録します。アプリからnoteへ公開操作は送られません。
会員CSVには個人情報が含まれるため、直接取り込みません。人がプラン別集計し、指定の数値CSVまたは手入力で保存します。

## 8. 公開前の受入確認

- 所有者以外が管理画面・ファイル・APIを利用できない。
- 正しいオーナーでログイン、1時間経過後に再ログインできる。
- 少額のAI上限で調査→企画→制作→QAを実サービスでテストする。
- 試作品を人が確認し、Excel/Googleスプレッドシートで計算と表示を確認する。
- 未承認・差し戻し・予定日前の配信が止まり、承認した同一版だけ配信準備へ進む。
- テストメールがiPhoneに届く。通知リンクから承認できる。
- 実際のnote各プラン、価格、退会条件、公開対象、ダウンロードを確認。
- iPhone Safari実機でログイン・ダウンロード・承認・差し戻しを試す。
- Cronの初回実行履歴を確認し、実行中断・失敗時の手動再試行を練習する。
